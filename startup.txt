============================================================
 TROUBLESHOOTING  (every failure hit this session + the fix)
============================================================

* Emulator "Segmentation fault" on launch
    Cause: __NV_PRIME_RENDER_OFFLOAD + -gpu host. NVIDIA GLX vs AMD
    Vulkan mismatch crashes libGL.
    Fix: drop the PRIME env vars, use -gpu angle_indirect
    (or -gpu swiftshader_indirect). See TERMINAL 1.

* Agent: every step "blocked_by_prism", Connection refused :8765
    Cause: PRISM text shield (:8765) not running. PRISM fails CLOSED —
    if it can't scan, it blocks everything (notifications, contacts,
    AND actions like open_app/tap). This is correct security behavior.
    Fix: start TERMINAL 2. Verify curl :8765/health = {"status":"ok"}.

* /v1/context hangs / "Android sidecar :8766 unreachable: timed out"
    Cause A: accessibility service not enabled (cold boot leaves it
      null/0). The handler blocks forever waiting for the a11y tree.
      Fix: TERMINAL 3 step 3.
    Cause B (fixed in APK): handler ran ~60 serial ONNX inferences on
      the NanoHTTPD thread. Already patched (L2 dropped from context
      path; Python re-scans via :8765). If you reverted the APK,
      rebuild.
    Client timeout was also raised 2s -> 8s in context_assembler.py.

* "Contact note BLOCKED: [Alice]" on a mail task
    Not a bug. /v1/context returns the whole device bundle every step
    (notifications+clipboard+sms+contacts+calendar), not task-scoped.
    With :8765 down it fail-closed-blocks all of it. With :8765 up,
    benign contacts scan clean and pass.

* Skill scores low cosine / wrong skill retrieved
    Only "name + first sentence" is embedded (prism_cli.py:244).
    If a skill's first sentence is technical (package paths, tool
    names) it ranks poorly. Re-add the skill with a task-language
    first sentence. Floor is _SKILL_MIN_COSINE=0.20 in
    context_assembler.py. Cosine = 1 - dist/2 (ChromaDB L2 space).
    KEEP/DROP + cosine is logged for the operator; it is NEVER
    passed to the agent prompt.

* Auto-memory saved with low trust (0.60) for "remember my name"
    Working as designed for AUTONOMOUS memories, BUT an explicit
    "remember/save to memory ..." task is now detected and stored
    origin=user trust=1.0 (agent_prism.py _is_explicit_save_request).
    Manual /memory save is always trust=1.0. Provisional priors only
    apply to memories the agent writes about its own execution.

* Gmail notifications only arrive on manual pull-to-refresh
    Emulator background sync gets killed. Whitelist Gmail:
      adb -s emulator-5554 shell cmd deviceidle whitelist +com.google.android.gm

* "/exit" tracebacks with TypeError: 'Event' object is not callable
    Fixed: AlertWatcher._stop renamed to _stop_evt (it shadowed
    Thread._stop). If it recurs you're on an old build.

* Skills/memories retrieve nothing or nonsense; log shows
  "[Embed] FAILED to load BAAI/bge-small-en-v1.5 ... Falling back"
    Cause: sentence-transformers missing, or no network for the first
    bge-small download. The store is bge-embedded; the default fallback
    model produces incompatible vectors -> garbage similarity.
    Fix: pip install -r requirements.txt (ensures sentence-transformers),
    ensure HF reachable once for the ~130MB download, restart. If the
    store got corrupted, restore + re-embed:
      python scripts/reembed_store.py --restore data/kb_backup_*.json

* Skill cosine values look different after an embedder change
    _SKILL_MIN_COSINE in context_assembler.py is embedder-specific
    (0.78 for bge-small, was 0.20 for the old MiniLM). Re-baseline it if
    PRISM_EMBED_MODEL changes; bge bunches scores into a high band.

* CLI shows "LLM: GROQ" / 401 from api.groq.com
    Default is now claude. If you see groq you passed --llm groq or
    are on an old prism_cli.py. Just run `python scripts/prism_cli.py`.
